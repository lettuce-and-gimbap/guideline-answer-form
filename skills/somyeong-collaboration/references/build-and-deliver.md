# 구현과 전달 기준

## 환경과 범위를 확인한다

현재 경로, 기존 파일, 실행 스크립트, 의존성, 사용 가능한 도구를 확인한 뒤 구현한다. 버전·호스트·포트를 임의로 가정하지 않는다. 기존 프로젝트의 구조를 이해하고 재사용할 수 있는 부분을 찾는다. 과제 범위에 맞지 않는 인증·외부 API·대규모 하네스를 관성적으로 추가하지 않는다.

작업 전에 명시된 필수 요구를 놓치지 않게 정리한다. 새 요구가 들어오면 현재 작업에 합치되, 이미 승인된 목표와 충돌하면 그 지점을 설명한다. 사용자가 제한한 파일, 분량, 출력 형식, 원본 유지 조건을 끝까지 지킨다.

수정한 소스가 실제 실행되는 파일인지 확인한다. 별도 번들·빌드·생성 파일을 제공하는 구조라면 필요한 재생성과 연결 상태를 확인한다. 소스만 바꾸고 사용자 화면에도 반영됐다고 말하지 않는다. 특정 프로젝트의 빌드 명령이나 캐시 정책을 다른 프로젝트에 그대로 복사하지 않는다.

## 상태 변화와 저장 결과를 다룬다

UI는 최초 진입뿐 아니라 입력 → 실행 → 결과 → 수정 또는 돌아가기의 흐름으로 검토한다. 기능에 해당하면 새로고침, 재접속, 중도 이탈, 저장 후 재열기도 확인한다. 모든 앱에 같은 기능을 추가하라는 뜻은 아니다. 과제에서 요구한 저장과 상태 유지가 실제로 되는지 확인한다.

최종 제출이나 되돌리기 어려운 동작이 있을 때는 사용자가 내용을 검토하고 이전 단계로 돌아갈 수 있어야 하는지 판단한다. 질문과 답, 항목과 수치가 서로 연결되어 보이게 해 결과를 해석할 수 있게 한다.

내보내기·인쇄·복사·다운로드를 요구하면 화면만 확인하고 끝내지 않는다. 저장된 파일을 다시 열어 필수 내용, 잘림, 빈 화면, 로딩 흔적, 링크 등을 확인한다. 확인할 수 없는 환경이면 사용자에게 구체적인 수동 확인 방법과 미확인 범위를 안내한다.

## 검증의 강도를 작업에 맞춘다

작은 문구 수정에는 영향 위치와 표시를 확인한다. 계산·데이터 변환에는 입력과 출력의 대응, 누락·중복·경계값을 확인한다. 기능 수정에는 정상 동작과 수정한 버그를 재현하는 흐름을 우선 확인한다. 관련 없는 검사를 무한히 늘리지 않는다.

기존 검사를 통과시키려고 기대값을 임의로 느슨하게 하거나 실패 조건을 삭제하지 않는다. 반복 실패하면 입력, 상태, 이벤트, 저장 시점, 렌더와 내보내기 경로 중 실제 원인을 좁힌다. 해결됐다고 선언하기 전에 같은 재현 조건에서 확인한다.

자동 화면 조작이 금지되면 사용자가 허용된 미리보기에서 직접 확인하도록 안내한다. 우회 도구나 외부 브라우저를 만들지 않는다. 서버 실행이 필요한 경우 실제 시작 로그에서 바인딩과 포트를 확인하며, 앱 미리보기 설정을 바꿀 때 다른 보안을 일괄 해제하지 않는다.

## 전달은 바로 사용할 수 있게 한다

전체 코드를 요구한 경우 현재 수정까지 반영된 완결 코드를 전달한다. 실제 편집 가능한 작업환경에서는 파일을 수정하고 그 결과와 실행 방법을 제공한다. 사용자가 부분 수정만 원하면 긴 전체 코드 출력으로 시간을 쓰지 않는다.

산출물은 요청한 경로와 형식에 저장한다. 파일을 만들었다면 다시 열어 기록된 결과를 확인하고 실제 파일 링크를 제공한다. 실행·저장·공개 배포는 각각 다른 상태이므로 구별해 보고한다. 커밋·푸시·배포는 해당 작업의 권한과 규정에 맞을 때만 수행한다.

전수 변환·대량 수정은 대상 목록과 성공·실패·보류 상태를 남기고 구간별로 저장해 재개할 수 있게 한다. 내용이 같은 파일이 여러 경로에 있으면 중복임을 확인한 뒤 처리 방식을 정한다. 대량 삭제나 원본 덮어쓰기를 검증 절차와 섞어 자동으로 수행하지 않는다.

마지막 보고는 핵심 동작, 실제 확인 방법과 결과, 남은 제한을 중심으로 쓴다. 사용자 경험과 직접 관련 없는 구현 세부사항은 필요할 때만 설명한다. ‘AI가 그렇게 말해서’라는 이유로 선택을 정당화하지 말고 요구·제약·근거에 연결한다.
